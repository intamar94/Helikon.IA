# Ciclo de dominio v1 — Helikon

El dominio de un conocimiento no se obtiene por completar pantallas. Se obtiene mediante evidencia.

## Flujo

Introducción → Aprender → Practicar → Romper → Resolver → Evaluar → Transferir → Dominar

## Reglas

- Una evaluación fallida identifica la competencia concreta que necesita refuerzo.
- El refuerzo usa una situación nueva; no repite literalmente la pregunta anterior.
- Los intentos son limitados y cada intento debe variar el problema.
- El dominio requiere evidencia de aplicación y transferencia, no solo reconocimiento.
- Al dominar, se actualizan competencias y se desbloquean únicamente los nodos cuyos prerrequisitos quedaron satisfechos.
- Después del dominio se programa recuperación espaciada para comprobar retención.

## Evidencia mínima

1. Comprensión conceptual.
2. Aplicación práctica.
3. Detección/corrección de un caso límite o fallo.
4. Transferencia a un contexto nuevo.
5. Evaluación final sin pistas.

## Estado de fallo

`evaluando → refuerzo`

El sistema debe conservar el motivo del fallo y el concepto afectado para que la siguiente experiencia sea adaptativa.

## Estado de dominio

`evaluando → dominado`

Al dominar se registra la evidencia, se actualiza el nivel de competencia y se recalculan los nodos disponibles del grafo.
